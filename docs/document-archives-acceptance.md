# 旧报价／旧发票 PDF 归档（功能①）

用户确认：旧单据只归档，不计入欠款和收入。功能②未实施。

## 实现范围

- 原报价／发票列表增加上传入口，历史归档直接并入原列表。独立「历史原件」区域已移除，共用搜索、排序、来源筛选和分页；不替换原手动新增、明细、签名或签回流程。
- 只要求 PDF 和已有客户。原编号、原日期均可空；导入时间为服务器完成归档的时间，以马来西亚时区显示。
- 独立 `document_archives`，没有金额、到期日或付款状态，不向 quotes、quote_items、invoices 写入；收入、待收款、财务报表、状态提醒的数据源不变。
- 浏览器复用现有 pdfjs-dist 读取最多前 10 页文字层；仅带入明确标签的编号、无歧义的年在前日期，不覆盖已填写字段。月份在前／日份在前的歧义日期留空。扫描／手写不做 OCR；含文字层不代表所有页面均已识别。
- 无新增应用依赖，无外部 OCR/AI 调用或识别服务费。保存原件仍使用现有 Supabase 额度。实际旧 PDF 样本尚未提供，未承诺其识别率。
- 支持选择、拖入、预览所选文件、重试识别、移除、保存、统一列表搜索／分页、查看／下载原件。
- 同类型的原编号检查普通单据和历史归档（忽略首尾空格及大小写）；返回重复提示后由用户确认另存。独立 UUID 路径不覆盖原件。普通单据的并发新增不受归档锁控制，检查以归档登记时可见记录为准。
- 上传开始后锁定该次元数据，失败保留文件和输入，可使用同一 UUID 安全重试。需更改资料时重新选择文件；不确定结果时先检查历史归档。
- 离开保护复用现有 InteractionProvider/useUnsaved，包括浏览器关闭／刷新提示。用户强制关闭浏览器后，出于浏览器限制无法保留内存中的本地 File，需要重新选择。

## 列表合并修正（2026-10-14）

本轮只修改前端呈现，不改后端 API、SQL、权限、统计计算或归档文件；不执行迁移，也不要求重新上传已有归档。

- 页面用带来源的展示行合并系统单据和归档，保持两个原始数据集合独立，归档不会被转换成 Invoice/Quote 业务对象。
- 每行标明「系统建立」或「历史归档」，来源筛选为全部／系统建立／历史归档；筛选只改变 URL 和展示，不发出写请求。
- 统一搜索支持编号、客户、状态和原件文件名；统一分页先合并、筛选、排序再分页，来源切换重置页码。
- 日期排序默认为最新日期优先：系统报价使用有效期、系统发票使用到期日，历史归档使用原单据日期。原报价接口未返回创建时间，因此前端不假装能按跨来源创建时间排序；原默认「最新建立」标签改为「日期：最晚优先」。
- 归档金额使用 null 表示未知，显示「—」，金额升序／降序均放在已知金额之后；未知日期同样置后。
- 系统单据操作保持原有路径；归档行只显示查看／下载原 PDF，原单据日期和导入时间仍分别显示。
- 状态／待收款／逾期入口仅匹配系统业务单据，不为归档伪造业务状态。
- 「全部」中即使只有归档也显示真实结果与总数。归档读取失败不当成空集合展示「尚未有资料」，而是显示读取失败及数量未加载；可以切换系统建立继续查看已加载业务单据。
- 清除搜索与筛选同时清除来源条件。撤回本轮前端差异仅影响列表布局，不删除数据库记录或 PDF。

## 上一轮迁移审阅记录

本任务未执行迁移；本轮不连接真实数据库核验其当前执行状态。以下内容保留作为归档功能的迁移影响说明，本次列表修正不需要额外迁移。

文件：`supabase/migrations/202610140001_add_document_archives.sql`。

具体变更：

1. 新增私有 Storage bucket `document-archives`，PDF-only、10 MB；若存在不符合设置的同名 bucket，迁移报错，不静默改变权限。
2. 新增 `public.document_archives` 和三个索引：客户外键、类型、可空原编号／原日期、客户名称快照、文件名／大小／SHA256／路径、上传人、完成标识和时间。客户／上传人外键为 RESTRICT，因此已有归档关联的客户／用户不能被直接删除；现有业务流程不新增删除动作。
3. 表启用 RLS，撤销浏览器角色直接访问；只向服务角色授予读取及指定 RPC 执行权限。新增此 bucket 的限制性 Storage 策略，阻止 anon/authenticated 绕过后端直接读写；不修改其他 bucket 策略或真实用户角色。
4. 三个 RPC：`can_access_document_archives`、`reserve_document_archive`、`complete_document_archive`。使用空 search_path、重新验证实时管理角色及客户；写入只经 RPC。
5. 每份完成的归档写一条现有 activity_logs，details.operation 为 historical_pdf_archived；幂等重试不重复写日志。普通单据和签名／签回表不变。

先登记为未完成 → 上传私有原件（不使用 upsert）→ 核对并确认完成。只有完成项进入归档列表／下载 API。重试遇到已存文件时校验相同哈希，拒绝覆盖不同内容。

Storage 与 PostgreSQL 不能组成同一事务，失败可能保留未完成登记或已上传但未完成确认的文件。它们不进入业务统计，保留用于重试；本次没有自动清理或删除任务。需要以后人工核对的情况包括用户在未确认结果时改用新 UUID。

**执行此迁移需要用户另行确认。** SQL 在事务内执行，不包含删除历史业务记录、清空测试资料、恢复旧测试数据或修改真实账号权限。未执行迁移时归档请求会失败，页面可提示重试，原业务接口照常独立使用。
