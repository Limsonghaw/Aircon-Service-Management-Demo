## 现有功能与缺口

现有老板常用签名、签署快照及签名版 PDF 使用 `owner_saved_signatures`、`signed_documents` 和独立私有存储空间。它们不能被客户上传文件替代。现有附件组件与 PO 功能提供 PDF 预览、下载、上传进度、失败保留选择、稳定附件编号重试及离开保护，可沿用交互模式，不改变 PO 或签署权限。

报价已有详情页；发票通过列表操作菜单和打印预览操作，没有独立发票详情页。建议在报价详情增加「客户签回 PDF」区域，在发票每行／手机卡片增加同名入口并打开独立附件面板。与普通 PDF 和老板签名版明确分开。

## 具体数据库方案

迁移草案：`supabase/migrations/202610080002_add_customer_returned_documents.sql`。

- 新建 `customer_returned_documents` 表：附件 ID、单据类型及 ID、报价／发票外键、原文件名、MIME、字节数、SHA-256、私有路径、上传人及时间。约束每份附件只关联一张实际存在的报价或发票。
- 新建私有 `customer-returned-documents` bucket，只接受 PDF，暂定每份 10 MB（10485760 字节），沿用现有附件限制；API 另校验真实文件内容。
- 新增附件历史查询索引；表启用 RLS；浏览器角色不得直接访问，后台普通写入也不得绕过登记函数。Storage 新限制只作用于该 bucket。
- 新增管理角色访问检查与登记函数；使用实际登录用户 ID，再核对实时 profile 的 owner/admin 角色。上传、查看和下载均核对单据／附件归属。
- 稳定附件 ID 支持相同内容重试；新增补传使用新 ID；不覆盖、不删除历史文件。登记成功才确认保存，登记与已有 `updated` 操作日志同事务提交。

## 流程影响及撤回

上传为可选，任意现有状态都可补传。不改报价／付款状态、不新增必填字段、不新增员工或客户门户权限，不将签回视为发票付款。已有老板签名及 PO 完全独立。

单据及上传人外键使用 RESTRICT：已有签回文件时禁止直接删除关联单据／profile，防止失去归属。再次检查确认报价与发票当前均无删除接口，因此没有新增删除功能或改动删除业务。

迁移只新增空表、bucket、索引、策略、函数，不回填或删除真实资料。不提供破坏性回滚；撤回代码需保留表与存储文件。若希望撤回后仍可从界面访问历史，需要保留管理端只读查看／下载入口。Storage 上传与数据库登记不是跨服务事务，失败时保留已上传对象，重试核对同一 ID 和哈希，不自动清理未知结果文件。
