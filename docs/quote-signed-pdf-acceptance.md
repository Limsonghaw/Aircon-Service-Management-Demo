# 第②项：报价普通 PDF 与老板签名版 PDF

日期：2026-10-08。本项代码完成，等待用户验收；不开始第③项。

## 发现与处理

普通 PDF 通过 `window.print()` 导出当前未签名预览。常用签名保存的是笔画，并不生成当前单据的 PDF。老板签名版由后端生成、存入私有 `signed-documents`，签名记录的下载链接读取该固定文件并检查 SHA-256。

只读检查当前 Supabase 中最近的 5 份报价签名记录，均有笔画；下载其中最新一份既有演示报价的原始 PDF，SHA-256 与记录一致，实际打开并渲染后，公司签名栏有笔迹。这个结论仅覆盖已检查的文件；用户当时点击的入口和具体报价尚未确认，不能推断所有历史文件都正常。

改动仅涉及三个前端文件：`QuoteDetailPage.tsx`、`DocumentPreview.tsx`、`DocumentSigning.tsx`。报价入口改为「PDF / 老板签名」；预览标明普通 PDF 无签名；下载标明「下载老板签名版 PDF」；常用签名按钮注明不生成 PDF；生成按钮及成功提示明确指向签名版下载。生成过程中禁用普通打印。共用预览／签名组件中的这些提示也适用于发票。

无数据库迁移、状态、权限或后端生成／下载逻辑变更。老板仍负责签署，管理角色仍可下载，员工权限保持原状。撤回这三个文件的本项差异不会删除常用签名、签名记录或历史 PDF。
