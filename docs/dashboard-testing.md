# Dashboard 验收与统计口径

## 范围

第 7 阶段的 Dashboard 小模块：统计、加载与失败状态、空资料、页面跳转和响应式布局。
不调整财务报表、支付模型、权限或数据库；无新依赖，无 migration。

## 指标口径

- 进行中的工作：状态为 `in_progress` 的工作数量。
- 待处理事项：已发送报价、未付款/部分付款/逾期发票、待检查费用的总条数。首页显示前 8 项，指标统计全部条数。
- 本月已完成：状态为 `completed` 且服务日期属于当前月份的工作。当前月份统一使用 `Asia/Kuala_Lumpur`，并非按完成状态变更时间计算。
- 已收款总额：所有 `paid` 发票金额，按分累计。不是本月实际收款，不包含部分付款。现有数据库没有单独的收款金额和收款日期，不能凭发票创建日期推算收款日期。
- 当前工作安排：所有未完成工作；详细筛选使用工作单页面。

加载中显示 `…`，失败显示 `—` 和重试按钮；失败不能显示假零或「没有待处理事项」。
财务数据采用同一批次的报价、发票、费用结果；其中一项失败时不发布不完整汇总。

## 自动测试

已有 Node.js 环境下，在 frontend 目录运行（Node 需支持 TypeScript strip-types）：

```sh
node --experimental-strip-types --test tests/dashboardSummary.test.mjs
```

7 项测试覆盖空资料、工作状态、服务月份边界、马来西亚跨月/跨年时间、发票付款状态、全年累计和金额精度。
继续运行现有前端 lint、TypeScript/Vite build 和后端测试；本轮后端 113 项通过。

## 浏览器验证

使用临时隔离测试页面加载真实 Dashboard 组件与 hooks，通过已知模拟 API 数据验证：

- 有资料：1 个进行中工作、5 项待办、1 个本月完成、RM 123.45 已付款总额；3 个未完成工作。
- 空资料：指标真实为零，待办和工作安排显示正确空态。
- 加载：4 个指标显示省略号，两个列表显示加载提示。
- 失败：4 个指标显示破折号，两个列表不显示假空态；工作及财务独立重试成功。
- 日历、报价详情、发票、费用和工作入口导航到预期路径。隔离页面只验证目标路径，目标页面的完整功能由各模块及后续整体测试覆盖。
- 320px、390px 手机宽度及 1280px 电脑宽度未发现横向溢出。

临时页面测试后移除，不修改账号或业务资料。截图含模拟测试数字，不是实际经营数据。
本轮没有通过老板真实登录会话逐条人工对账；建议上线前核对真实发票与首页金额。
